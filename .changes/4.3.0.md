## 4.3.0 - 2026-11-19

### ✨ Added

* [#1306](https://github.com/microsoft/terraform-provider-power-platform/issues/1306) `powerplatform_data_record` has a new optional `relationship_removal_behavior` attribute. Set it to `disassociate` to only remove the link (a `$ref` request) when an item is removed from a collection-valued relationship and keep the related row. The default, `delete_related_record`, keeps the existing behavior of deleting the related row

### 🪲 Fixed

* [#1300](https://github.com/microsoft/terraform-provider-power-platform/issues/1300) Retry `powerplatform_environment` creation on transient `GraphServerError` (HTTP 500) responses from the environment create API, recovering an environment the failed request already created by its validated Dataverse domain instead of creating a duplicate
* [#1308](https://github.com/microsoft/terraform-provider-power-platform/issues/1308) Record a powerplatform_environment in state when its create times out while the create operation is still running, so Terraform destroys it instead of leaving it untracked
* [#1308](https://github.com/microsoft/terraform-provider-power-platform/issues/1308) Default the powerplatform_environment create timeout to 60 minutes, because creating an environment includes provisioning its Dataverse database
* [#1308](https://github.com/microsoft/terraform-provider-power-platform/issues/1308) Keep waiting for a lifecycle operation when a single poll of it fails transiently instead of failing the whole operation
* [#1308](https://github.com/microsoft/terraform-provider-power-platform/issues/1308) Retry a request rejected with 401 up to 5 times with a fresh token instead of 2, to ride out brief token issuance delays
* [#1308](https://github.com/microsoft/terraform-provider-power-platform/issues/1308) Retry a 401 from a Dataverse organization the provider created within the last hour for up to 10 minutes instead of 5 times, and log at WARN how long each run of 401 answers lasted
* [#1308](https://github.com/microsoft/terraform-provider-power-platform/issues/1308) Keep polling a powerplatform_tenant_isolation_policy operation that answers 404 OperationNotFound for up to 2 minutes, wait before the first poll, and wait between polls that answer 409 instead of polling again at once
* [#1319](https://github.com/microsoft/terraform-provider-power-platform/issues/1319) Recreate a `powerplatform_rbac_role_assignment` whose created assignment never appears in the role assignment listing, deleting the unlisted assignment by its id first, instead of failing after a 10 minute wait
* [#1308](https://github.com/microsoft/terraform-provider-power-platform/issues/1308) Retry the solution staging of powerplatform_solution and powerplatform_managed_solution for up to 10 minutes while a Dataverse organization the provider created within the last hour reports that the caller has not been assigned any roles, and log at WARN how long the wait lasted
* [#1326](https://github.com/microsoft/terraform-provider-power-platform/issues/1326) Importing `powerplatform_connection` (ID `{environment_id}/{connector_name}/{connection_id}`) no longer panics, and importing `powerplatform_solution` no longer fails with `ENVIRONMENT_URL_NOT_FOUND`, because `ImportState` now populates `environment_id` (and `name` for connections) from the import ID; malformed import IDs and empty environment or tenant IDs now return a diagnostic instead of crashing
* [#1327](https://github.com/microsoft/terraform-provider-power-platform/issues/1327) Remove `powerplatform_data_record` from state when its Dataverse row was deleted outside Terraform instead of failing the refresh with `Client error when reading powerplatform_data_record`
* [#1332](https://github.com/microsoft/terraform-provider-power-platform/issues/1332) Importing `powerplatform_connection_share` no longer fails with a `Value Conversion Error` on `principal`, because `ImportState` now populates `environment_id`, `connector_name`, `connection_id` and `principal.entra_object_id` from the import ID `{environment_id}/{connector_name}/{connection_id}/{principal_entra_object_id}`; the principal GUID may be given in any case, and malformed import IDs return `Invalid import ID`

### 🚨 Security

* [#1304](https://github.com/microsoft/terraform-provider-power-platform/issues/1304) Infer OAuth scopes only from the parsed HTTPS host of known Power Platform and Dataverse endpoints; reject untrusted hosts and malformed URLs before requesting a token
