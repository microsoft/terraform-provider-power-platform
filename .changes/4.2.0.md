## 4.2.0 - 2026-09-08

### ✨ Added

* [#1089](https://github.com/microsoft/terraform-provider-power-platform/issues/1089) Add x-ms-useragent header to all backend requests when telemetry is not opted out
* [#1133](https://github.com/microsoft/terraform-provider-power-platform/issues/1133) Add powerplatform_publisher resource and powerplatform_publishers data source with Dataverse CRUD support and nested address handling. **Contributor: @AdamCoulterOz**.
* [#1225](https://github.com/microsoft/terraform-provider-power-platform/issues/1225) Add `powerplatform_environment_variable_value` resource to manage current environment-scoped values for existing environment variable definitions; the resource manages only the value, definitions ship in solutions. It creates the value record for a definition that has none and updates the existing one otherwise. **Contributor: @AdamCoulterOz**.
* [#1143](https://github.com/microsoft/terraform-provider-power-platform/issues/1143) Add `powerplatform_managed_solution` resource for identity-driven managed solution deployment with apply-time package validation for managed state, connection references, environment variable satisfiability, and dependency versions. **Contributor: @AdamCoulterOz**.
* [#946](https://github.com/microsoft/terraform-provider-power-platform/issues/946) Add powerplatform_environment_disaster_recovery resource to enable/disable disaster recovery for Power Platform environments
* [#1210](https://github.com/microsoft/terraform-provider-power-platform/issues/1210) Add `advanced_connector_policies_only`, `content_security_policy` and `advanced_connector_policies` rules to `powerplatform_environment_group_rule_set`, along with a computed `policy_id` attribute. These rules are served by the rule-based policies API rather than the rule sets API used by the remaining rules. An existing policy already assigned to the environment group is adopted rather than replaced, and a policy created by the resource is deleted again when the resource is destroyed. **Contributor: @metjuperry**.
* [#1209](https://github.com/microsoft/terraform-provider-power-platform/issues/1209) `powerplatform_environment` and `powerplatform_environments` adding `allow_microsoft_365_services` and `allow_flex_routing` attributes. **Contributor: @ferronsw**.
* [#1190](https://github.com/microsoft/terraform-provider-power-platform/issues/1190) Added `powerplatform_rbac_role_assignment` resource to assign a Power Platform role to an enterprise application, user or group. The required `scope_type` names where it applies: `tenant`, `environment` with `environment_id`, or `environment_group` with `environment_group_id`. The role is selected by `role_definition_id` or `role_definition_name`. **Contributors: @metjuperry, @AdamCoulterOz**.
* [#1190](https://github.com/microsoft/terraform-provider-power-platform/issues/1190) Added `powerplatform_role_definitions` data source to list the Power Platform roles that can be assigned at tenant, environment group or environment scope. **Contributor: @metjuperry**.
* [#1190](https://github.com/microsoft/terraform-provider-power-platform/issues/1190) Added `powerplatform_rbac_role_assignments` data source to list role assignments. The required `scope_type` names which assignments to read: `tenant`, `environment` with `environment_id`, or `environment_group` with `environment_group_id`. **Contributors: @metjuperry, @AdamCoulterOz**.
* [#1223](https://github.com/microsoft/terraform-provider-power-platform/issues/1223) Add `powerplatform_application_user` resource for managing non-interactive Dataverse application users (service principals) with business unit selection, live-user adoption on create, and disabled-state reconciliation. **Contributor: @AdamCoulterOz**.
* [#1224](https://github.com/microsoft/terraform-provider-power-platform/issues/1224) Add `powerplatform_security_role_assignment` resource for assigning a Dataverse security role to a user, application user or team, independently of the principal's lifecycle. Set `system_user_id` or `team_id` for the principal, and `security_role_name` or `security_role_id` for the role. **Contributor: @AdamCoulterOz**.
* [#1226](https://github.com/microsoft/terraform-provider-power-platform/issues/1226) Add `privacy_and_security.blocked_attachment_extensions` support to `powerplatform_environment_settings` resource and data source. **Contributor: @AdamCoulterOz**.
* [#1227](https://github.com/microsoft/terraform-provider-power-platform/issues/1227) Add `macro_region` to `powerplatform_environment` and the `powerplatform_environments` data source, plus a new `powerplatform_macro_regions` data source. Environment creation previously failed on tenants that provision by macro region, where the service rejects `location` outright.

### ⚰️ Deprecated

* [#860](https://github.com/microsoft/terraform-provider-power-platform/issues/860) docs: announce the v5.0.0 removal of the `powerplatform_rest` resource. Migrate to purpose-built resources before upgrading. The `powerplatform_rest_query` data source is not affected. The resource remains supported until v5.0.0.
* [#1136](https://github.com/microsoft/terraform-provider-power-platform/issues/1136) docs: announce the v5.0.0 replacement of `powerplatform_solution` by `powerplatform_managed_solution` and `powerplatform_unmanaged_solution`. Plan migration according to the solution type when upgrading. The existing resource remains supported until v5.0.0.
* [#969](https://github.com/microsoft/terraform-provider-power-platform/issues/969) docs: announce the v5.0.0 removal of `powerplatform_tenant_capacity.tenant_id`. Remove configurations and references using this attribute; capacity is fetched for the tenant configured in the provider. The attribute remains supported until v5.0.0.
* [#959](https://github.com/microsoft/terraform-provider-power-platform/issues/959) docs: announce v5.0.0 deprecations for `powerplatform_tenant_settings` (resource and data source). `disable_survey_feedback`, `disable_nps_comments_reachout`, and `power_platform.intelligence.enable_open_ai_bot_publishing` will be renamed or moved within tenant settings. Update configurations and references to match the v5.0.0 schema when upgrading. `power_platform.power_apps.disable_create_from_image` and `power_platform.power_apps.disable_create_from_figma` will be removed with no replacement. Current attributes remain supported until v5.0.0.

### 📚 Documentation

* [#1210](https://github.com/microsoft/terraform-provider-power-platform/issues/1210) Removed the service principal limitation and preview notes from `powerplatform_environment_group_rule_set`; the full create, read, update and delete lifecycle is verified against service principal authentication by acceptance tests. **Contributor: @metjuperry**.
* [#1266](https://github.com/microsoft/terraform-provider-power-platform/issues/1266) docs: announce an upcoming breaking change to `powerplatform_user` imports in v5.0.0. Import IDs will require the composite `environment_id/user_aad_id` format, where `user_aad_id` is the Microsoft Entra object ID (`aad_id`). Legacy single-ID imports will no longer be supported; update import commands and import blocks when upgrading. The resource itself is not deprecated, and current import behavior remains unchanged until v5.0.0.
* [#1266](https://github.com/microsoft/terraform-provider-power-platform/issues/1266) docs: announce an upcoming breaking change to the `powerplatform_locations` response structure in v5.0.0. The data source will additionally support macro regions, changing its response structure. Update expressions and module outputs consuming its results to match the v5.0.0 schema when upgrading. The data source itself is not deprecated, and its current response structure remains unchanged until v5.0.0.
